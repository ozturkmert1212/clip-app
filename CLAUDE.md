# ClipApp

An "instant replay" clipping app for macOS. It captures the screen continuously, keeps the last N seconds in memory already encoded, and saves them as an mp4 on a global shortcut. The main window lists the saved clips, plays and trims them; the menu bar icon stays as a helper.

## Build / run

```bash
xcodegen generate            # project.yml -> ClipApp.xcodeproj (not kept in the repo)
xcodebuild -project ClipApp.xcodeproj -scheme ClipApp -configuration Debug -derivedDataPath build build
open build/Build/Products/Debug/ClipApp.app
```

For a release build use `-configuration Release`; the output is `build/Build/Products/Release/ClipApp.app`.

- After adding or removing files, run `xcodegen generate` again.
- `ClipApp/Info.plist` and `ClipApp/ClipApp.entitlements` are generated by XcodeGen from `project.yml`; change them through `project.yml`, not by hand.
- Signing is automatic with an Apple Development certificate (`DEVELOPMENT_TEAM: CRHSYX58TX`), sandbox off, hardened runtime on. Because the signing identity is stable, the Screen Recording permission survives rebuilds. If the certificate is missing, add `-allowProvisioningUpdates` to the build.
- Swift language mode 5 (`SWIFT_VERSION: "5.0"`), minimum macOS 13.

## Architecture

Intended data flow:

```
SCStream -> CaptureManager -> EncoderPipeline (VideoToolbox H.264) -> RingBuffer
                           -> system audio -> AudioPipeline (16 bit PCM) -> RingBuffer
AVCaptureSession -> MicrophoneCapture -> AudioPipeline (16 bit PCM) ---> RingBuffer
shortcut -> HotkeyManager -> ClipWriter (RingBuffer snapshot -> mp4: video passthrough, audio AAC)
```

Current code:

- `ClipApp/App/ClipAppApp.swift` — `Main` (the entry point: pins the language, then starts the SwiftUI app), the `MenuBarExtra` scene and `AppDelegate`; the shared objects (`PermissionManager`, `WindowManager`, `ClipController`) are owned by `AppDelegate`. At launch the main window opens unless `SettingsStore.openWindowAtLaunch` is off or the system started the app as a login item (read from the launch Apple event); a Dock click or a second launch reopens it (`applicationShouldHandleReopen`). Closing the last window never quits.
- `ClipApp/App/ClipController.swift` — builds the pipeline (`CaptureManager` -> `EncoderPipeline` -> `RingBuffer`, system audio and `MicrophoneCapture` -> `AudioPipeline` -> `RingBuffer`) and turns a request from the shortcut or the menu into a clip. Whenever `SettingsStore` changes, `applySettings()` pushes every setting down; each component ignores a value it already has. The microphone only runs while the setting is on and the permission is granted; a permission change triggers `applySettings()` too. It watches `CaptureManager.state` and tells the user: immediately when the permission is missing, when capture fails to recover for more than 5 seconds, and when the selected source disappears and capture falls back to the main display. Every message goes out two ways (`report`): a system notification and, if `SettingsStore.showHUD` is on, the `HUD`.
- `ClipApp/Capture/CaptureManager.swift` — the `SCStream` lifecycle. The source (`CaptureSource`: display / window / application) is resolved again on every start; if it is gone, capture falls back to the main display. All (re)starts go through a single `restart()`: stream errors (with growing delay), display parameter changes, wake from sleep, the target application launching or quitting. Frames arrive in `StreamOutput` on the capture queue and are handed out through `onVideoFrame`. System audio comes from the same stream (`capturesAudio`, 48 kHz stereo, our own audio excluded) on a separate queue; turning it on or off rebuilds the stream. With a window or application source only that application's audio arrives. With a display source the filter is `SCContentFilter(display:excludingApplications:exceptingWindows:)`: Notification Center (`com.apple.notificationcenterui`) and ClipApp itself are excluded as applications, which keeps the main window, its sheets and menus and the HUD out of clips. `excludedWindowIDs` (the HUD) is only passed through `exceptingWindows` as a fallback when ClipApp is not found in the shareable content. While applications are excluded, another application's window passed as an exception is not captured either (measured). The applications are looked up separately with `onScreenWindowsOnly: false` (`exclusions()`) and the log says "N own window(s) and M app(s) excluded" (normally 0 and 2). If Notification Center restarts, the stream is rebuilt.
- `ClipApp/Capture/MicrophoneCapture.swift` — captures the default input device with `AVCaptureSession` (SCStream's microphone is macOS 15+ only). It asks for 48 kHz output so it can be mixed with system audio. Timestamps are converted from the session clock to the host clock. Rebuilt when the default device changes and on a session error.
- `ClipApp/Encoding/EncoderPipeline.swift` — `VTCompressionSession` (hardware H.264, real time, no B-frames, 2 s keyframe interval). The session is rebuilt on the first frame, when the frame size changes and after `configure(fps:bitrate:)`.
- `ClipApp/Encoding/AudioPipeline.swift` — converts incoming LPCM (Float32 or Int16, planar or interleaved) to 16 bit interleaved stereo PCM while applying the level (mono is copied to both channels). One per audio source.
- `ClipApp/Buffer/RingBuffer.swift` — encoded video samples and PCM audio per track (`AudioTrack`: system, microphone), guarded by a lock. It only trims when a keyframe arrives, and by whole GOPs. When the format (resolution) changes the old content is dropped, because a single mp4 track cannot change parameter sets. There is also a byte cap (`SettingsStore.bufferByteLimit` = buffer length × target bitrate × 3): beyond it the oldest GOPs are dropped regardless of age, the GOP being filled always stays. While the cap is active the buffer is shorter than configured and the menu shows an info line (`ClipController.byteLimitedSeconds`). Audio is trimmed by duration; when an audio format changes, that track's old content is dropped.
- `ClipApp/Clip/ClipWriter.swift` — mp4 through `AVAssetWriter`: video passthrough, audio AAC. With `mixAudio` on, the sources are summed into one track (if their formats match); off, each source becomes its own track (order: system, microphone). An unwritable folder and a full disk come back as distinct errors and the partial file is deleted. The file name comes from `SettingsStore.clipFileName`; if it exists, `_2`, `_3` are appended.
- `ClipApp/Hotkey/HotkeyManager.swift` — global shortcut through KeyboardShortcuts (default ⌃⌥⌘R, changeable in Settings). When triggered it logs at notice level in the `hotkey` category.
- `ClipApp/Permissions/PermissionManager.swift` — Screen Recording, microphone and notification permission state (refreshed every 5 seconds), requests, System Settings deep links, relaunch.
- `ClipApp/Notifications/Notifier.swift` — system notifications: "Clip saved" (with a Show in Finder action) and error messages. Without the permission it silently does nothing.
- `ClipApp/Settings/SettingsStore.swift` — `UserDefaults` backed settings: buffer length, resolution, FPS, bitrate, capture source, save folder, file name format (`{date}`, `{time}`, `{source}`), on/off and level (0–2, 1 = unchanged) for system audio and microphone, mixing audio into one track (default on), the on-screen message (`showHUD`, default on) and its corner (`hudCorner`), opening the main window at launch (`openWindowAtLaunch`, default on), interface language (`language`). Stored values are validated against the offered options. Launch at login goes through `SMAppService`; the system owns that state, it is not written to `UserDefaults`. Because the login item is registered for the app's current path, the option can only be turned on when running from `/Applications` (or `~/Applications`).
- `ClipApp/Settings/AppLanguage.swift` — the interface language (English, Turkish), see "Localization".
- `ClipApp/Library/` — `ClipLibrary` (the mp4 files in the save folder, newest first; watches the folder with a `DispatchSource` and also reloads when `ClipController.lastResult` changes, because the folder reports a new file but not that it is complete), `ThumbnailCache` (`AVAssetImageGenerator` off the main thread, JPEG files under `~/Library/Caches/<bundle id>/Thumbnails`, keyed by path, size and modification date), `ClipTrimmer` (writes `<name> (trimmed).mp4` next to the original: `AVAssetExportSession` passthrough by default; the precise option decodes with `AVAssetReader` and encodes H.264 with `AVAssetWriter` at the source track's `estimatedDataRate`, size, frame timestamps and color tags, copying every audio track unchanged).
- `ClipApp/UI/` — `MainWindowView` (sidebar with the Clips and Settings tabs and, at its bottom, the status strip: capture state, buffered seconds, the save button), `ClipsView` (thumbnail grid, context menu, empty state), `ClipPlayerView` (AVKit player with the trim timeline), `MenuBarView` (menu), `SettingsView` (the Settings tab), `PermissionView` (permissions), `WindowManager` (hosts SwiftUI views in AppKit windows; with `LSUIElement` this is the reliable way to open a window conditionally at launch. `LSUIElement` stays in Info.plist: showing the main window switches the activation policy to `.regular`, closing it back to `.accessory`, so the Dock icon exists exactly while the window is open. The main window is 960×640 by default, 760×480 minimum, and remembers its frame), `HUD` (a borderless `NSPanel` shown for 2.5 seconds in the chosen corner: ignores mouse events, at `.screenSaver` level, on all Spaces and above full screen apps. The corner is `SettingsStore.hudCorner`, default top left; top right is where notification banners appear, so the HUD would sit on top of the banner there).
- `ClipApp/Resources/` — `Localizable.xcstrings` and the per-language `InfoPlist.strings`.

## Localization

- The source language is English (`developmentLanguage: en`), Turkish is the second language. Every user-visible string lives in `ClipApp/Resources/Localizable.xcstrings`; the key is the English text. SwiftUI literals are looked up as `LocalizedStringKey`; everything outside a view (notifications, HUD, errors, window titles) and every menu bar menu item uses `AppLanguage.string(_:)`, never `String(localized:)` directly (that one follows the launch language). Log messages and code comments stay in English and are never localized.
- The catalog is maintained by hand (Xcode also syncs it when the project is built in the IDE). `SWIFT_EMIT_LOC_STRINGS` is on, so after a build the keys the compiler found are in `build/Build/Intermediates.noindex/ClipApp.build/<config>/ClipApp.build/Objects-normal/arm64/*.stringsdata`; comparing those with the catalog's keys shows a missing or stale entry. A key missing from the catalog shows up in English in the Turkish interface.
- Usage descriptions (currently only `NSMicrophoneUsageDescription`) are localized in `ClipApp/Resources/{en,tr}.lproj/InfoPlist.strings`; the value in `project.yml` is the English fallback.
- The language does not follow the system and changes without a restart. `AppLanguage.string(_:)` looks a string up in the chosen language's own `.lproj` bundle on every call (English has no table there, its keys are the text); `LanguageRoot` wraps every hosted SwiftUI tree (main window, permission window, menu) and puts `SettingsStore.language.locale` into the environment, which is what the literals resolve against. Things that hold a finished string have to be refreshed by hand: the permission window title (`WindowManager`), the notification action title (`Notifier.registerActions()`, run before each clip notification), the source list in Settings (reloaded on change), and pickers whose rows are plain strings (`.id(settings.language)`).
- Text supplied by macOS stays in the launch language until a restart: the app menu, the shortcut recorder, the player controls, open panels, display names (`NSScreen.localizedName`, visible in the status strip and the menu). For that part `AppLanguage` still writes the app's own `AppleLanguages`, and `Main.main()` calls `AppLanguage.applyAtLaunch()` before SwiftUI starts, so without a stored choice the app comes up in English even on a Turkish system. Settings shows a note and a Restart button while `SettingsStore.language` differs from `AppLanguage.launched`.
- Verified on macOS 27.2 in Debug and Release, switching in a running app in both directions (English to Turkish, and launched in Turkish then to English): the main window, the actual `NSMenu` items of the menu bar menu, the text handed to the HUD, delivered notifications and the notification action title all changed at once. The HUD cannot be screenshotted (`sharingType = .none`), so its text was read from what `show` receives.

## Notes

Notification banners: macOS hides notifications by default while the screen is shared or recorded ("display shared"). The notification lands in Notification Center but no banner appears; the user has to allow notifications during sharing under System Settings > Notifications. That switch cannot be flipped from code; the permission window offers a button that opens the page, and the real feedback is the HUD. Even with that switch on, banners stay out of clips, because Notification Center is excluded from the display filter. Side effect: desktop widgets are Notification Center windows too, so they do not appear in display clips.

Keeping our own interface out of clips: ClipApp is excluded from display capture as an application, and the HUD panel additionally has `sharingType = .none`. On recent macOS versions ScreenCaptureKit is known to ignore `sharingType`, so the filter is the path to rely on; if one of the two is ever removed, the filter has to stay. Measured on macOS 27.2 at filter level, not from a saved clip: a still taken through a display filter that excludes ClipApp and Notification Center did not contain the main window, the same still without exclusions did (mean difference to the window's own image 15.8 against 0.4 on a 0–255 scale). The HUD under the application exclusion was not measured again; the earlier measurement (HUD and banner rectangles over a magenta background never changed in the clip) was taken with the HUD excluded by window ID.

Trimming (measured on a 1080p60 clip, range 5.3–12.7 s): passthrough export does not cut on a keyframe. It keeps the frames back to the previous keyframe (0.6 s here, at most one 2 s GOP) and hides them with an edit list, like `ClipWriter` does, so the result plays as exactly 7.400 s and its first visible frame is the source frame at 5.3 s; a player that ignores edit lists shows the extra frames. The precise option on the same range: 40.01 Mbps against 40.27 Mbps for the source track (99 %), 1920×1080, the same 425 frames, no hidden frames, PSNR 41.7 dB / SSIM 0.984 against the source, audio identical to the passthrough result. An export preset is not used for it because `AVAssetExportPresetHighestQuality` picked 15.5 Mbps for this clip. Cancelling mid-way throws `CancellationError` and removes the partial file (tested from the command line, not through the Cancel button).

The encoder only aims at the average bitrate: on content that does not compress, such as pure noise, it goes far above the target (~150 Mbps measured at 1080p60), which is why RingBuffer has a byte cap: on such content the clip comes out shorter than configured but memory stays bounded. On compressible synthetic moving content it stayed below the target.

To read logs use `/usr/bin/log` (zsh has its own `log` builtin): `/usr/bin/log show --predicate 'subsystem == "com.mertozturk.ClipApp"' --last 1m --info`.

Known limit: the global shortcut does not fire in full screen (exclusive) games, the game grabs the keyboard; it works in borderless/windowed mode.

Clip timing (read before changing):

- ScreenCaptureKit only delivers a frame when the screen changes. So the end of a clip is not the newest sample but the host clock at the moment of the request; `endSession` holds the last frame until then.
- A clip is written from the last keyframe before the requested start. The frames before the start (lead-in) only exist so the first visible frame can be decoded; the writer trims them from playback with an edit list.
- Lead-in frames are shifted forward so the last one lands exactly on the clip start. That way the lead-in is at most one GOP long even if the screen was static for a long time, and the clip is exactly N seconds.
- The duration of the last video frame is extended to the end of the clip. `endSession` alone is not enough: with an audio track present the video track ends at the last frame, and ffmpeg based players do not see the extension.
- Audio is laid out gaplessly on the clip timeline (`audioTimeline`): buffers are placed end to end, holes larger than 20 ms and the start and end of the clip are filled with silence. Every audio track is therefore exactly as long as the clip and the AAC encoder is unaffected by timestamp jitter.

Design rules:

- Raw frames are never kept in memory; RingBuffer stores video only as encoded `CMSampleBuffer`s and trims by GOP, a clip always starts with a keyframe.
- Audio is deliberately kept as PCM and encoded to AAC when the clip is written: it can be cut and padded with sample accuracy, and the writer takes care of encoder delay (priming). 16 bit stereo 48 kHz is 192 KB per second, small next to the video.
- All tracks are kept on the same host clock and rebased from one common start time when the clip is written.
- Writing a clip does not stop capture.

## Open items

- The shortcut does not fire in full screen games (the game grabs the keyboard); it works in borderless. Possible fix: a mouse side button / controller button trigger.
- Not tested by hand in a real game: audio/video sync, a mixed clip with microphone, the notification banner, the login item.
- No notarization/Developer ID; currently Apple Development signing, which only runs on this Mac.
- While the memory cap is active, clips come out shorter than configured.
- Main window, not tested by hand: clicking through the grid, the context menu actions, dragging the trim handles, the window coming forward when opened from the menu, and a launch as a login item staying in the menu bar.
- Trimming a clip saved with separate audio tracks was not tested.
